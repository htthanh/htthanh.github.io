Template Method pattern: vấn đề & ý tưởng

Định nghĩa (GoF · nhóm Behavioral)

  • Định nghĩa khung (skeleton) của một thuật toán trong một phương thức của lớp cha — gọi là template method.
  • Một số bước trong khung được để lại cho lớp con cài đặt (hàm virtual).
  • Lớp con đổi được nội dung từng bước nhưng không đổi được thứ tự các bước.

Bài toán ví dụ: pha đồ uống

Pha trà và pha cà phê đều theo cùng một quy trình 4 bước. Nếu viết 2 lớp riêng thì code các bước giống nhau bị chép lại 2 lần, sau này sửa quy trình phải sửa ở 2 nơi.

+ public · # protected · - private · nghiêng = trừu tượng (pure virtual)

① Template method — prepare()

Public, không virtual (hoặc final) → lớp con không thể đổi thứ tự. Nó chỉ gọi các bước bên dưới theo đúng trình tự.

② Bước cố định (concrete operation)

Lớp cha cài sẵn, mọi lớp con dùng chung: boilWater(), pourInCup().

③ Bước trừu tượng (primitive operation)

virtual … = 0 → lớp con bắt buộc cài: brew(), addCondiments().

④ Hook

Hàm virtual có sẵn cài đặt mặc định (thường rỗng / trả true) → lớp con tùy chọn override để can thiệp vào khung: wantsCondiments().

Biến thể NVI trong C++ · ưu / nhược · khi nào dùng

C++ cho phép lớp con override hàm ảo private (chỉ là không gọi được nó). Có thể khai báo virtual void prepare() final nếu template method buộc phải là hàm ảo.

Nhấn → để chạy từng bước.

✓ Ưu điểm

  • Loại bỏ code trùng lặp
  • Kiểm soát chặt thứ tự thuật toán
  • Mở rộng bằng lớp con mới, không sửa lớp cha
  • Hook cho phép tùy biến có kiểm soát

✗ Nhược điểm

  • Dựa trên kế thừa → gắn chặt lớp con với lớp cha
  • Khung càng nhiều bước càng khó hiểu
  • Chọn hành vi lúc biên dịch, không đổi được lúc chạy

Khi nào dùng?

  • Nhiều lớp có cùng quy trình, chỉ khác vài bước: xuất file (mở → ghi header → ghi data → đóng), xử lý request (xác thực → xử lý → ghi log).
  • Framework gọi code người dùng: vòng lặp game init / update / render, unit test SetUp / TestBody / TearDown.

Tổng kết: Template Method

Ý tưởng

Lớp cha giữ khung thuật toán trong một hàm không virtual (template method); các bước khác nhau để lớp con cài bằng hàm virtual.

3 loại bước

Cố định (lớp cha cài, thường private) · trừu tượng = 0 (lớp con bắt buộc cài) · hook (virtual có mặc định, lớp con tùy chọn).

Cơ chế

Template method gọi hàm ảo → vtable chọn hàm của lớp con thật sự. Lớp cha gọi xuống lớp con: “Don't call us, we'll call you”.

Trong C++

Dạng NVI: public non-virtual + private virtual. Có thể dùng final. Nhớ virtual destructor.
