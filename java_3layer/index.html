Mô hình 3 lớp
3-Layer Model · DTO · JDBC

Project DemoJDBC quản lý nhà cung cấp (bảng SUPPLIERS): presentation (console) → bus (nghiệp vụ) → dao (JDBC) → MySQL, dữ liệu đi giữa các lớp bằng dto. Mỗi lớp một thư mục. Đủ CRUD: thêm, xem, tìm, sửa, xóa.

Code lấy từ DemoJDBC, đã bổ sung đầy đủ CRUD cho SupplierBUS và menu console cho Main. Toàn bộ đã chạy thử với JDK 25, MySQL 8.0 (Docker), mysql-connector-j 9.1.0. Lệnh viết cho macOS/Linux, có kèm cách gõ trên Windows.

S07

JDBC driver: cần file jar nào?

📦 mysql-connector-j-9.1.0.jar ≈ 2,5 MB

MySQL Connector/J — driver Type 4 (100% Java, nói chuyện trực tiếp với MySQL qua mạng). Đặt trong DemoJDBC/lib/ (đã có sẵn).

Cách 1 · tải bằng lệnh (Maven Central)

Cách 2 · tải từ trang MySQL

dev.mysql.com/downloads/connector/j/ → Select OS: Platform Independent → ZIP Archive → giải nén, chỉ lấy file .jar.

Cách 3 · Maven / Gradle

com.mysql:mysql-connector-j:9.1.0

🔍 Trong jar có META-INF/services/java.sql.Driver → từ JDBC 4.0 DriverManager tự nạp driver, không cần Class.forName("com.mysql.cj.jdbc.Driver").
⚠ com.mysql.jdbc.Driver là tên của bản 5.x. Bản 8.x / 9.x dùng com.mysql.cj.jdbc.Driver.

A07

Vì sao dùng PreparedStatement với ? — SQL injection

Người dùng nhập tên:

x' OR '1'='1

delete from SUPPLIERS where SUP_NAME = 'x' OR '1'='1'
💥 xóa TOÀN BỘ bảng
where SUP_NAME = "x' OR '1'='1" ← chỉ là 1 giá trị
→ 0 rows affected ✓
  • Chống SQL injection
  • Tự xử lý dấu nháy: tên O'Brien Coffee không làm hỏng câu SQL
  • Đúng kiểu dữ liệu (setInt cho SUP_ID, setString cho tên…)

Tổng kết

presentation/

Main: menu, Scanner, in bảng. Đóng hộp DTO, gọi SupplierBUS, bắt lỗi để báo người dùng. Không SQL.

bus/

SupplierBUS: checkID, validate (tên, STATE, ZIP) rồi gọi SupplierDAO. Dữ liệu sai dừng ở đây.

dao/

UtilityDAO mở Connection; SupplierDAO dùng JDBC: PreparedStatement, ResultSet, getGeneratedKeys.

dto/

SupplierDTO: 6 field ↔ 6 cột. “Chiếc hộp” đi xuống (C, U) và đi lên (R) giữa các lớp.
