2.2

Quên định nghĩa lại → lỗi khi link · cách viết C++17

// Linux, g++ (GNU ld):undefined reference to `Counter::count'// macOS, clang++:Undefined symbols for architecture arm64: "Counter::count", referenced from: _main

Vì sao biên dịch OK mà link lỗi?

Compiler chỉ cần khai báo để kiểm tra kiểu → biên dịch được. Đến bước link, cần tìm ô nhớ thật của Counter::count — nhưng không file nào định nghĩa nó → lỗi.

  • static const int (kiểu nguyên, hằng) được gán giá trị ngay trong lớp.
  • Từ C++17: inline static → khai báo + định nghĩa cùng một chỗ, không cần dòng int Config::count = 0; nữa.
  • Trong môn học (và code C++ cũ) vẫn dùng cách chuẩn: khai báo trong lớp + định nghĩa lại ngoài lớp.

3.2

Hàm nào truy xuất được gì?

11: error: invalid use of member 'x' in static member function12: error: call to non-static member function without an object argument13: error: invalid use of 'this' outside of a non-static member function

Thông báo lỗi của clang++ (đã chạy thử). g++ báo tương tự, ví dụ “cannot call member function … without object”.

Gọi từ ↓ · truy xuất →thuộc tính

đối tượng (g)		hàm
tĩnh (p)
Hàm của đối tượng (f)
Hàm tĩnh (q)

Vì sao hàm tĩnh không dùng được x, f()?

Hàm tĩnh không có this → không biết đang nói tới x của đối tượng nào (a1.x? a2.x? hay chưa có đối tượng nào?). Muốn dùng thì phải có đối tượng cụ thể truyền vào: static void q(A& a) { a.x = 4; a.f(); } ✓

VD2: hàm UCLN nên là hàm tĩnh

Khi nào dùng thuộc tính tĩnh?

Biến “toàn cục” cho một lớp: bộ đếm đối tượng, mã tự tăng, cấu hình chung, đối tượng duy nhất của Singleton.

Khi nào dùng hàm tĩnh?

Hàm không cần thuộc tính/hàm của đối tượng: UCLN, Math::max, hàm đọc thuộc tính tĩnh, getInstance().

Lỗi hay gặp

Quên int A::t = 0; → lỗi link · dùng x/this trong hàm tĩnh → lỗi biên dịch · quên đếm trong hàm dựng sao chép.
